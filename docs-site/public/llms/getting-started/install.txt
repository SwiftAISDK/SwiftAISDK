# Install

Source URL: https://swiftaisdk.github.io/SwiftAISDK/getting-started/install/

Add SwiftAISDK to your package manifest:

```swift
// Package.swift
dependencies: [
    .package(url: "https://github.com/SwiftAISDK/SwiftAISDK.git", from: "3.0.0"),
],
targets: [
    .target(
        name: "YourApp",
        dependencies: [
            .product(name: "SwiftAISDK", package: "SwiftAISDK"),
        ]
    ),
]
```

An application can pin the validated umbrella release with SwiftPM's `exact:`
requirement. Commit `Package.resolved` to preserve every dependency revision;
an exact umbrella version alone does not freeze the provider/core graph.
Production applications should not depend on the moving `main` branch.

Then import the library:

```swift
import SwiftAISDK
```

## Credentials

Provider factories read upstream-style environment variables by default:

| Provider | Default environment variable |
| --- | --- |
| OpenAI | `OPENAI_API_KEY` |
| Anthropic | `ANTHROPIC_API_KEY` |
| Google Generative AI | `GOOGLE_GENERATIVE_AI_API_KEY` or `GEMINI_API_KEY` |

You can also pass credentials explicitly:

```swift
let provider = try AIProviders.openAI(
    settings: ProviderSettings(apiKey: "your-api-key")
)
```

Use explicit settings when you need custom headers, a custom base URL, a mock transport, or per-environment credentials.

## Independent modular packages

All 52 independent packages are published: core, 49 provider adapters, MCP and UI.
Core and Anthropic are at `1.1.0`; the other packages are at `1.0.0`.
Choose packages from the [catalog](https://github.com/SwiftAISDK/SwiftAISDK/blob/main/Docs/PackageCatalog.md),
or use the complete 3.0 umbrella above. See the [3.0 migration guide](https://swiftaisdk.github.io/SwiftAISDK/getting-started/migrating-to-3/)
for native imports, configuration and compatibility details.

For a modular OpenAI client:

```swift
// Package.swift
 dependencies: [
    .package(url: "https://github.com/SwiftAISDK/swift-ai-core.git", from: "1.1.0"),
    .package(url: "https://github.com/SwiftAISDK/swift-ai-openai.git", from: "1.0.0"),
 ],
 targets: [
    .target(name: "YourApp", dependencies: [
        .product(name: "SwiftAI", package: "swift-ai-core"),
        .product(name: "SwiftAIOpenAI", package: "swift-ai-openai"),
    ]),
 ]
```

```swift
import SwiftAI
import SwiftAIOpenAI

let provider = try AIProviders.openAI(
    configuration: OpenAIProviderSettings(apiKey: "your-api-key")
)
let model = try provider.languageModel("gpt-4.1")
let result = try await AI.generateText(
    model: model,
    request: .init(messages: [.user("Hello")])
)
```

Anthropic uses `SwiftAIAnthropic` and `AnthropicProviderSettings`. A generic
compatible endpoint uses `SwiftAIOpenAICompatible` with
`OpenAICompatibleProviderSettings(name:baseURL:...)`. Native factories accept
`configuration:`; the 3.0 compatibility API continues to accept `settings:`.
Native clients pass model objects or use explicit registries; core does not
initialize an implicit Gateway.

The canonical repository contains complete offline `AnthropicOnly`,
`OpenAICompatibleOnly`, `OpenAIOnly` and `MixedProviders` examples. OpenAI shares
chat/completion, embedding and image wire code with the compatible package;
selecting it does not require unrelated providers, MCP or UI. See the
[3.0 migration guide](/SwiftAISDK/getting-started/migrating-to-3/).

Provider versions can be selected independently as long as their shared dependency
requirements intersect. SwiftPM resolves one version per package identity. Swift
release numbers do not track npm release numbers. Applications should commit their
`Package.resolved`; reusable libraries should normally express compatible ranges.

The 3.0 umbrella shares model and request types with the modular packages and
preserves the ordinary `import SwiftAISDK` API. Existing 2.x tags remain usable,
but their separately defined types cannot be mixed with modular values. Moving
modules is not a binary compatibility guarantee; rebuild your application.
The [tested 3.0 release set](https://github.com/SwiftAISDK/SwiftAISDK/blob/3.0.0/Releases/umbrella/3.0.0.json)
records the complete dependency selection.
