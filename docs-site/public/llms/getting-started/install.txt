# Install

Source URL: https://swiftaisdk.github.io/SwiftAISDK/getting-started/install/

Add SwiftAISDK to your package manifest:

```swift
// Package.swift
dependencies: [
    .package(url: "https://github.com/SwiftAISDK/SwiftAISDK.git", from: "3.4.0"),
],
targets: [
    .target(
        name: "YourApp",
        dependencies: [
            .product(name: "SwiftAISDK", package: "SwiftAISDK"),
        ]
    ),
]
```

An application can pin the validated umbrella release with SwiftPM's `exact:`
requirement. Commit `Package.resolved` to preserve every dependency revision;
an exact umbrella version alone does not freeze the provider/core graph.
Production applications should not depend on the moving `main` branch.

Then import the library:

```swift
import SwiftAISDK
```

## Agent skill

Coding agents such as Claude Code, Codex and Cursor can install the SwiftAISDK
skill from this repository with the open [`skills`](https://github.com/vercel-labs/skills) CLI:

```sh
npx skills add SwiftAISDK/SwiftAISDK
```

The skill lives at [`skills/swiftaisdk/SKILL.md`](https://github.com/SwiftAISDK/SwiftAISDK/blob/main/skills/swiftaisdk/SKILL.md).
It tells the agent how to add the package, pick a provider with `AIProviders`
and `languageModel(_:)`, call `generateText`, `streamText`, `Output` and
`AITool`, configure credentials and pin versions. It also points the agent at
these docs as Markdown: [`/llms.txt`](https://swiftaisdk.github.io/SwiftAISDK/llms.txt)
lists every page, and each page is available at its URL with `.md` in place of
the trailing slash, for example `/core/tools.md`.

Pass `-a ` to install for one agent only, or `-g` to install globally.
Run the command again to pick up a newer version of the skill.

## Credentials

Provider factories read upstream-style environment variables by default:

| Provider | Default environment variable |
| --- | --- |
| OpenAI | `OPENAI_API_KEY` |
| Anthropic | `ANTHROPIC_API_KEY` |
| Google Generative AI | `GOOGLE_GENERATIVE_AI_API_KEY` or `GEMINI_API_KEY` |

You can also pass credentials explicitly:

```swift
let provider = try AIProviders.openAI(
    settings: ProviderSettings(apiKey: "your-api-key")
)
```

Use explicit settings when you need custom headers, a custom base URL, a mock transport, or per-environment credentials.

## Independent modular packages

All 55 independent packages are published: core, 52 provider adapters, MCP and UI.
The 2026-11-15 set updates 36 units: 31 patch releases, additive core 1.5.0 and
HeyGen 1.2.0, plus initial Tencent, Parallel and ScaleDown 1.0.0. Nineteen
unchanged packages retain their existing versions. npm and Swift versions are
independent. Select only the products your application needs, or use the complete
3.4 umbrella above.

The [package catalog](https://github.com/SwiftAISDK/SwiftAISDK/blob/main/Docs/PackageCatalog.md)
lists products and dependency requirements. Exact published versions and verified
release refs are recorded in [release verification](https://github.com/SwiftAISDK/SwiftAISDK/blob/main/Docs/ReleaseVerification20261115.json).

For a modular OpenAI client:

```swift
// Package.swift
 dependencies: [
    .package(url: "https://github.com/SwiftAISDK/swift-ai-core.git", from: "1.5.0"),
    .package(url: "https://github.com/SwiftAISDK/swift-ai-openai.git", from: "1.3.1"),
 ],
 targets: [
    .target(name: "YourApp", dependencies: [
        .product(name: "SwiftAI", package: "swift-ai-core"),
        .product(name: "SwiftAIOpenAI", package: "swift-ai-openai"),
    ]),
 ]
```

```swift
import SwiftAI
import SwiftAIOpenAI

let provider = try AIProviders.openAI(
    configuration: OpenAIProviderSettings(apiKey: "your-api-key")
)
let model = try provider.languageModel("gpt-4.1")
let result = try await AI.generateText(
    model: model,
    request: .init(messages: [.user("Hello")])
)
```

Anthropic uses `SwiftAIAnthropic` and `AnthropicProviderSettings`. A generic
compatible endpoint uses `SwiftAIOpenAICompatible` with
`OpenAICompatibleProviderSettings(name:baseURL:...)`. Native factories accept
`configuration:`; the 3.x compatibility API continues to accept `settings:`.
Native clients pass model objects or use explicit registries; core does not
initialize an implicit Gateway.

The canonical repository contains complete offline `AnthropicOnly`,
`OpenAICompatibleOnly`, `OpenAIOnly` and `MixedProviders` examples. OpenAI shares
chat/completion, embedding and image wire code with the compatible package;
selecting it does not require unrelated providers, MCP or UI. See the
[3.0 migration guide](/SwiftAISDK/getting-started/migrating-to-3/).

Provider versions can be selected independently as long as their shared dependency
requirements intersect. SwiftPM resolves one version per package identity. Swift
release numbers do not track npm release numbers. Applications should commit their
`Package.resolved`; reusable libraries should normally express compatible ranges.

The 3.4 umbrella shares model and request types with the modular packages and
preserves the ordinary `import SwiftAISDK` API. Existing 2.x tags remain usable,
but their separately defined types cannot be mixed with modular values. Moving
modules is not a binary compatibility guarantee; rebuild your application.
The [tested 3.4 release set](https://github.com/SwiftAISDK/SwiftAISDK/blob/main/Releases/umbrella/3.4.0.json)
records the complete dependency selection after actual-tag verification.

This release adds Tencent TokenHub/VOD, Parallel decisions and ScaleDown
decisions/extraction, HeyGen decisions, explicit-secret streaming tool-approval
replay and per-output video URL/media-type descriptors. Core is at least 1.5.0
and HeyGen at least 1.2.0 in the umbrella because its compatibility API exposes
these additions. See the [weekly audit](https://github.com/SwiftAISDK/SwiftAISDK/blob/main/Docs/WeeklyUpstreamAudit20261115.md)
for every npm/Swift version, release ref, verification result and retained gap.
