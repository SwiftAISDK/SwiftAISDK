# Generate text

Source URL: /core/generate-text/

Use `generateText` when you want a complete response before continuing your workflow.

```swift title="Examples/Sources/GenerateText/main.swift"
import SwiftAISDK

@main
struct GenerateTextExample {
    static func main() async throws {
        let provider = try AIProviders.openAI()
        let model = try provider.languageModel("gpt-6.1-sol")

        let result = try await model.generateText("Write one sentence about Swift concurrency.")

        print(result.text)
    }
}
```

## Request Options

Common options map to provider-agnostic model settings:

- `temperature`, `topP`, `topK`
- `maxOutputTokens`
- `stopSequences`
- `seed`
- `headers`
- `providerOptions`
- `extraBody`
- `abortSignal`
- `retryPolicy`, `timeoutNanoseconds`, and `telemetry`

Use `providerOptions` for documented provider-specific behavior. Use `extraBody` only as a low-level escape hatch when the provider has not yet grown a typed option.

```swift
let result = try await model.generateText(
    "Be concise.",
    options: LanguageGenerationOptions(
        providerOptions: [
            "openai": [
                "parallelToolCalls": false,
                "store": false,
            ],
        ]
    )
)
```

## Results

`TextGenerationResult` includes the normalized text plus metadata you can use for logging, billing, and debugging:

- `content`
- `text`
- `reasoning`
- `finishReason`
- `usage`
- `files`
- `sources`
- `toolCalls`
- `toolResults`
- `toolApprovalRequests`
- `toolApprovalResponses`
- `steps`
- `responseMessages`
- `warnings`
- `requestMetadata`
- `providerMetadata`
- `responseMetadata`

`content` preserves the ordered result parts, including text, reasoning, files, sources, tool calls, tool results, approval requests, approval responses, and custom provider parts. The convenience arrays are derived from the same content when possible.

Generated file and reasoning-file parts that contain `data:` or HTTP(S) URLs
are materialized into `AIStreamFile.data` before the result is returned. Remote
downloads enforce the shared private-host, redirect, size, and abort checks;
provider credentials are not forwarded to an unrelated origin. Provider file
references remain references and are not downloaded.

The URL checks do not yet pin a DNS answer to the connection address. If your
application accepts provider-selected remote files in a hostile network
environment, treat resolver-level DNS rebinding protection as a remaining
transport gap.

## Message pruning

`pruneMessages(..., reasoning: .all)` and `.beforeLastMessage` remove both
textual `.reasoning` and `.reasoningFile` parts within the selected scope.
Ordinary `.file` content is retained.

When you enable tools, `steps` records each model/tool loop step and `responseMessages` contains the assistant/tool messages that can be appended to the next request or stored in conversation history.

## Experimental steering

Create one `AISteering` for each generation. `steer` queues user text or user content for the next model step, after that step's tool work finishes. It returns a receipt whose async `value` never throws. Reusing an ID returns the original receipt; reusing a steering object in another generation throws.

```swift
let steering = AI.experimentalCreateSteering()
let receipt = steering.steer("Keep the answer concise", id: "style")
let result = try await AI.generateText(
    model: model,
    prompt: "Explain the tradeoffs",
    maxSteps: 4,
    experimentalSteering: steering
)
let outcome = await receipt.value
```

Messages queued before the run start reach step zero. Messages queued during a step can continue a completed answer, subject to `maxSteps` and `stopWhen`. Pending messages do not continue an errored or interrupted step, and unresolved tool results or approvals stop the run. A receipt reports either the receiving step number or `finished`, `removed-by-prepare-step`, `stop-condition`, `waiting-for-tool-results`, `aborted`, or `error`.

`prepareStep` receives the newly queued messages in `experimentalSteeringMessages`. Returning a replacement request can remove them; retaining equivalent user content counts as delivery. Each `AIToolStep.experimentalSteeringMessages` records only messages actually sent in that step. `initialRequest` remains the original request, and `responseMessages` contains generated assistant/tool messages, so steering messages remain separate when rebuilding conversation state. The final `text` is the final step's answer; prior step content and response messages remain available in the result.

Set an explicit step limit for steering. Swift retains its existing prompt/tool-loop default of five steps and agent default of twenty; the single request overload permits one step. `AIOutput` overloads also accept steering.

Use `steering.queue("Next task", id: "task-2")` to wait until the current task
finishes before starting another. Queued messages are promoted one at a time;
`steer` messages take precedence at the next step boundary. A truncated response
does not start the next queued task. Both methods share the same idempotent ID
and receipt rules. Normal completion, abort and the step limit settle messages
that were never delivered.

## Failed-step callbacks

`onStepError` receives `AIGenerateTextStepErrorEvent`, including the step number, provider/model identity, request, previous steps and original error. It fires once after retries fail, including an aborted or timed out `generateText` call. Successful steps do not fire it. Callback failures do not replace the generation error.

`AIToolLoopAgent` accepts constructor `onStepError`, `onError` and `onAbort` callbacks. `generate` invokes `onError` before rethrowing ordinary failures; aborts and timeouts are excluded. Its `onAbort` callback belongs to streaming. Pass steering through `AIAgentCallOptions(experimentalSteering: steering)`.
