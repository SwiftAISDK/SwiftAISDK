# Telemetry

Source URL: https://swiftaisdk.github.io/SwiftAISDK/core/telemetry/

Use telemetry when you want structured events for observability, debugging, billing, or product analytics. Telemetry is opt-in: pass `Telemetry.Options` on a call, or register integrations globally and pass enabled telemetry options. Calls with `telemetry: nil` do not record events.

```swift title="Examples/Sources/Telemetry/main.swift"
import SwiftAISDK

struct ConsoleTelemetry: Telemetry.Integration {
    func record(_ event: Telemetry.Event) async {
        print("\(event.kind.rawValue) \(event.operationID) \(event.providerID)")
    }
}

@main
struct TelemetryExample {
    static func main() async throws {
        let provider = try AIProviders.openAI()
        let model = try provider.languageModel("gpt-6.1-sol")

        let result = try await model.generateText(
            "Summarize this release note.",
            options: LanguageGenerationOptions(
                telemetry: Telemetry.Options(
                    functionID: "release.summary",
                    metadata: [
                        "tenant": .string("acme"),
                        "source": .string("docs"),
                    ],
                    integrations: [ConsoleTelemetry()]
                )
            )
        )

        print(result.text)
    }
}
```

`ConsoleTelemetry` is not an SDK type: the example defines it as a minimal
`Telemetry.Integration` that prints each event. Later snippets on this page
reuse it, so copy it into your project or substitute your own integration.

## Integrations

Implement `Telemetry.Integration` to receive `Telemetry.Event` values. The default `executeLanguageModelCall` and `executeTool` implementations simply run the underlying operation, so most integrations only need `record(_:)`.

```swift
struct MetricsTelemetry: Telemetry.Integration {
    func record(_ event: Telemetry.Event) async {
        if event.kind == .end {
            print(event.durationNanoseconds ?? 0)
            print(event.usage?.totalTokens ?? 0)
        }
    }
}
```

Register shared integrations once, then pass `Telemetry.Options()` to calls that should use the registered integrations.

```swift
Telemetry.register(MetricsTelemetry())

let result = try await model.generateText(
    "Explain this issue.",
    options: LanguageGenerationOptions(
        telemetry: Telemetry.Options(functionID: "support.explain")
    )
)
```

Per-call `integrations` override the registered integrations for that call.

```swift
let result = try await model.generateImage(
    "A compact app icon.",
    telemetry: Telemetry.Options(integrations: [ConsoleTelemetry()])
)
```

Disable telemetry for a call with `Telemetry.Options.disabled`.

```swift
let result = try await model.generateText(
    "Do not record this call.",
    options: LanguageGenerationOptions(telemetry: .disabled)
)
```

## Events

Telemetry events carry the operation, provider, model, call ID, duration, usage, warnings, metadata, and provider response details when available.

- `start` when a facade operation begins.
- `retry` before a retry delay.
- `end` when an operation completes successfully.
- `abort` when the caller aborts the operation.
- `error` when an operation fails.
- `stepStart` and `stepEnd` for multi-step tool loops.
- `modelCallStart` and `modelCallEnd` around a decision or evaluation model call.
- `stepError` when a text-generation step fails.
- `toolStart`, `toolEnd`, and `toolError` for tool execution.

Operation IDs by call:

| Area | Operation IDs |
| --- | --- |
| Text and objects | `ai.generateText`, `ai.streamText`, `ai.generateObject`, `ai.streamObject` |
| Embeddings and reranking | `ai.embed`, `ai.embedMany`, `ai.rerank` |
| Images and video | `ai.generateImage`, `ai.generateVideo` |
| Audio | `ai.generateSpeech`, `ai.transcribe`, `ai.streamTranscribe`, `ai.generateAudio`, `ai.transformAudio` |
| Decisions and evaluation | `ai.decide`, `ai.decide.doDecide`, `ai.evaluate`, `ai.evaluate.doEvaluate` |
| Provider files and skills | `ai.uploadFile`, `ai.getFileMetadata`, `ai.downloadFile`, `ai.deleteFile`, `ai.uploadSkill` |

Tool loop events use suffixed operation IDs such as `ai.generateText.step` and
`ai.generateText.tool`. Decisions and evaluations report the inner provider
call with `modelCallStart` and `modelCallEnd` under their `.doDecide` and
`.doEvaluate` IDs.

[Extraction](https://swiftaisdk.github.io/SwiftAISDK/core/extract/), [batches](https://swiftaisdk.github.io/SwiftAISDK/core/batch-text/),
[streaming speech](https://swiftaisdk.github.io/SwiftAISDK/core/stream-speech/) and [dubbing](https://swiftaisdk.github.io/SwiftAISDK/core/dubbing/) do not emit
telemetry events; instrument those calls in your own code.

## Audio usage

Audio calls expose native billing JSON in `Telemetry.Event.providerUsage`,
separately from language/embedding `TokenUsage`. Unary speech/transcription
results and streaming transcription finishes also expose `usage`.
`AI.streamTranscribe` measures bytes as the provider consumes chunks and emits
one terminal end/error/abort event. Speech output records length and content
type without including generated audio bytes.

## Privacy

Telemetry can include prompts, tool arguments, generated output, provider metadata, and response metadata. Turn off input or output recording when events leave your process or go to a third-party backend.

Provider models can also supply a `telemetryRedactor`. It sanitizes only the
SDK-owned metadata copies sent to telemetry integrations; prompts, tool results,
application context and the values returned to your code are unchanged. If the
redactor fails, the affected metadata is omitted. It is not a general secret
detector, so keep input/output recording off for sensitive content.

```swift
let telemetry = Telemetry.Options(
    includesInput: false,
    includesOutput: false,
    functionID: "chat.reply",
    metadata: ["environment": .string("production")]
)

let result = try await model.generateText(
    "Use private context from the app.",
    options: LanguageGenerationOptions(telemetry: telemetry)
)
```

`includesInput` and `includesOutput` are copied onto each event so downstream integrations can preserve the caller's redaction intent.

Decisions and evaluations can also carry request-local runtime context. Callbacks receive the
complete dictionary, while telemetry receives only keys explicitly allowlisted
with `includeRuntimeContext`:

```swift
let telemetry = Telemetry.Options(
    functionID: "evaluation.safety",
    includeRuntimeContext: [
        "tenant": true,
        "requestSecret": false
    ]
)
```

If the allowlist is omitted, telemetry records no runtime-context
keys. This keeps application-only callback context from leaking to an
observability integration by default.

## Wrapping Execution

Integrations can wrap model calls and tools by implementing `executeLanguageModelCall` or `executeTool`. Always call `context.execute()` unless the integration intentionally blocks the operation.

```swift
struct TimingTelemetry: Telemetry.Integration {
    func record(_ event: Telemetry.Event) async {}

    func executeLanguageModelCall<Output: Sendable>(
        _ context: Telemetry.LanguageModelCallContext<Output>
    ) async throws -> Output {
        let started = DispatchTime.now().uptimeNanoseconds
        defer {
            let elapsed = DispatchTime.now().uptimeNanoseconds - started
            print("\(context.operationID) took \(elapsed) ns")
        }
        return try await context.execute()
    }
}
```

Execution wrappers compose in the order integrations are registered or passed on the call.

## Streams

Streaming telemetry records the start event before the stream emits parts and records a terminal event when the stream ends, fails, or is aborted. Stream failures surface through the `AsyncThrowingStream`, so collect telemetry and consume the stream in the same task boundary when you need correlated logs.

When [`streamRetries`](https://swiftaisdk.github.io/SwiftAISDK/core/stream-text/#retry-behavior) recovers a stream after
output has started, telemetry emits a `retry` event with the incremented
attempt, the configured stream-retry maximum and zero delay, under the same
call ID. Setup retries from `retryPolicy` report their delays separately.

```swift
do {
    for try await part in model.streamText(
        "Write this response incrementally.",
        options: LanguageGenerationOptions(
            telemetry: Telemetry.Options(
                functionID: "writer.stream",
                integrations: [ConsoleTelemetry()]
            )
        )
    ) {
        print(part)
    }
} catch {
    print("Stream failed: \(error)")
}
```

## Contract version and failed steps

Events emitted by the telemetry dispatcher contain `aiVersion`, the version of
the AI SDK telemetry contract the event follows. Language-model and tool
execution contexts expose the same optional field. It is absent on manually
constructed contexts unless assigned; dispatch adds it to a copy and preserves
the caller's value.

`Telemetry.Event.Kind.stepError` closes a failed text-generation step before the call's terminal error/abort event. Its input contains the step number when input recording is enabled. Streaming provider error chunks still complete their step; streaming aborts and timeouts emit abort events instead of failed-step events. Input/output and runtime-context inclusion settings apply to these events too.

## Request origins and content capture

Providers may expose the actual endpoint in low-level `AIRequestMetadata.url`.
High-level text/object results and streams sanitize it to an HTTP(S) origin,
removing credentials, paths, queries and fragments. `Telemetry.Event.requestURL`
uses the same origin policy and remains available when content capture is off.

Disabling `includesInput` or `includesOutput` filters the corresponding SDK-owned
provider payloads, nested raw request/response bodies and error descriptions.
Returned generation results remain available to the caller. Application-supplied
telemetry metadata and integration context remain the application's responsibility.
