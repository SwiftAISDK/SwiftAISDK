## Current reviewed behavior

The provider exposes `extractionModel(_:)` for experimental typed nullable field extraction through Responses. `providerOptions.openai.textFormat` fixes the initial text format independently of Output parsing; empty system messages can replay `textFormatUpdate`, `reasoningEffortUpdate` and `additionalTools` at their original position. Format changes require GPT-6 or later with standard reasoning and no automatic compaction/truncation. Combine consecutive format and reasoning changes in one empty control message. Additional tools accept function, custom and namespace definitions; hosted adapters also read OpenAI tool-result options.

Set `promptCacheOptions.comparisonResponseId` to request comparison diagnostics. `providerMetadata.openai.promptCacheDiagnostics` preserves their raw fields across unary, streaming and batch results. OpenAI tool credentials are removed from telemetry copies while request/response values returned to applications remain intact. Image file, mask and markup downloads use the configured raw transport, without Azure provider credentials.

## Decisions and current Responses behavior

Use `provider.decisionModel("gpt-6-luna")` with [`AI.experimentalDecide`](../../core/decide/). OpenAI Decisions send `/decisions`, named questions and inline image evidence; the experimental Evaluation entry points remain available through the same native implementation. Choice, score and boolean questions can omit instructions. Boolean criteria still become predicate instructions. The native Decisions endpoint ignores `maxOutputTokens` and `reasoning`, reporting an unsupported warning for each supplied setting.

GPT-6-sol/luna sampling and logprobs follow the final effective reasoning effort, including configuration updates. Typed tool errors are wrapped as `{ "error": value }` in OpenAI requests. Failed/incomplete web-search results keep error/status metadata in generation, streaming and batch results. Stored assistant references retain structured-output schema breakpoints.

[`Batch downloads`](../../core/batch-text/) accept `ProviderSettings.batchResultDownloads` with a default 64 MiB UTF-8 row limit.

## Citation and history parity

Responses text content exposes `citations` independently of `result.sources`; streaming text-end parts carry the same citations. Citation sources use stable URL or file IDs and retain provider UTF-16 offsets. Retrieved web URLs and deduplicated file-search documents populate standalone sources, including uncited retrieved documents. Annotation sources remain a fallback when retrieval data is absent; `file_path` annotations remain standalone sources only.

For tools loaded during a conversation, attach `providerMetadata: ["openai": ["additionalTools": [...]]]` to an ordinary `AIToolResult`. Each strict function definition requires `type: "function"`, a nonempty `name`, and object `parameters`, with optional `description` and `strict`. The request inserts a developer `additional_tools` item immediately after that result. Set a function tool's `providerOptions.openai.omitFromRequestTools` to `true` to retain local execution and validation while omitting its top-level definition. Such tools cannot be forced or allow-listed until they are available through history.

Stored reasoning-model assistant text replays its content when the preceding reasoning was pruned. With `store: false`, provider-executed web-search results replay search/open-page/find-in-page actions. Custom tool streaming declares `inputEncoding: .text`. `webSearchPreview` is deprecated; use `webSearch`.

## Prompt cache prewarming and shell controls

Responses accepts `providerOptions.openai.promptCacheOptions` with `mode: "implicit"` or `"explicit"`, `ttl: "30m"` or `"12h"`, and optional `prewarm: true`. A prewarm response or stream may contain no text and zero output tokens. Cache-write totals remain available in `TokenUsage`; `rawValue.input_tokens_details.cache_write_tokens_details` preserves the 30-minute and 12-hour token breakdown. User text parts forward `providerMetadata.openai.promptCacheBreakpoint`, including `ttl: "12h"` with `mode: "explicit"`, to the corresponding input content entry.

Shell calls are marked `providerExecuted` for container environments and remain client calls for local execution. Shell tool-call input preserves `action.timeoutMs` and `action.maxOutputLength` when OpenAI supplies them. Shell results expose `maxOutputLength`; replaying assistant history with `store: false` or sending a tool result keeps that output limit. Null controls are omitted in generated and streamed tool input/results.

## Transcription languages

Transcription normalizes recognized English language names and lowercase two-letter codes. When `language` is absent or unrecognized, exactly one valid entry in the returned `languages` list supplies `result.language`; mixed-language responses leave it unset. `providerMetadata.openai.languages` preserves the detected list, including an empty list, alongside diarized `segments`. Unknown language names and locale strings such as `en-US` no longer appear as normalized language codes.
## Final-answer JSON and incomplete streams

For JSON Responses, the last message marked `final_answer` is exposed as
`TextGenerationResult.structuredOutputText` for structured parsing. Full `text`,
`content`, citations and message metadata still include draft messages. A missing
selection uses concatenated text; an empty selection stays explicit. Ordinary
text requests retain their existing full-content behavior.

Chat, Completion and Responses streams that end without a provider completion
signal finish as `interrupted`. Preserve the partial output and choose whether
to retry; tool execution and automatic continuation stop for that response.

## Current model and credential behavior

`OpenAIProviderSettings.apiKeyProvider` accepts an async throwing closure. It runs before each authenticated HTTP request and server WebSocket connection, including Files, Skills and Batch requests; explicit provider/request authorization headers retain precedence. Static `apiKey` remains supported. `getResolvedServerWebSocketConfig()` resolves rotating credentials for direct Live connections; the existing synchronous configuration method remains available for static credentials.

Portable `reasoning` is mapped to the nearest supported effort, preferring a lower effort and never silently disabling reasoning. Explicit `providerOptions.openai.reasoningEffort` is sent unchanged. GPT-5.6 Chat function tools select effort `none` unless provider options override it; use Responses when combining those tools with reasoning. GPT-6.1 Terra supports effort `none` and sampling in that mode. Chat maps `max` to its highest supported effort; Responses can send `max` to supporting models. GPT-5 retains prompt cache retention and Responses logprobs while reasoning.

Decisions accepts `providerOptions.openai.promptCacheKey`. Object JSON evidence and nonempty arrays of objects use native `input_json` within 32 container levels, 10,000 values and 256 KiB of UTF-8 JSON. Other values and larger evidence retain their JSON text representation. JSON Schema `propertyNames` without an explicit type is removed with a compatibility warning; an explicit non-string type is rejected. A web-search item still marked `searching` at completion is an error result.

`provider.streamingTranscriptionModel("gpt-transcribe")` exposes native incremental transcription. `gpt-live-transcribe` and the existing `gpt-realtime-whisper` alias also support streaming; dated snapshots are accepted. Supply `OpenAIProviderSettings.webSocketTransport` for a custom native connection. The new models send language hints as `languages`; `gpt-transcribe` ignores `streaming.delay` with a warning. The Live and realtime-whisper families require streaming. REST transcription leaves response format unset unless requested, except Whisper (`verbose_json`) and diarization (`diarized_json`); segment timestamps default only with `verbose_json`. Duration falls back to duration-billed usage, while token usage does not invent a duration.

## Refusals, tools and image controls

Chat and Responses retain refusal text, ordered content and log probabilities.
A refusal with a normal stop maps to `contentFilter`; a client tool call retains
its finish precedence. Responses streams and batch results preserve refusal
content and item/phase metadata. Low-level request metadata records the actual
endpoint; high-level results expose only its origin.

Set a message-level `providerMetadata.openai.name` for system/developer/user or
assistant names. Tool messages warn and omit the name. Content-part metadata does
not supply a message name. Secure MCP tools accept `tunnelID` as an exclusive
target alternative; code interpreter supports memory limits and disabled/allowlist
network policies, including domain secrets.

GPT Image 2.6 accepts complexity, safety identifiers and GIF frame-count/duration
controls for generation. GIF edits and mask-plus-markup combinations reject before
I/O. Edit markup can be supplied as a data URL or downloaded URL; download aborts
propagate.

Shared transcription `timestampGranularities` supplies word/segment requests when
provider-specific timestamps are absent. Only `verbose_json` sends timestamp
controls; `diarized_json` retains its own segments. Results expose independent
`words`, and unsupported or excluded timing requests warn. REST language/keyword
hint arrays use `languages[]`/`keywords[]`; empty arrays are omitted. Streaming
models warn for unsupported hints.
