## Package

`@ai-sdk/xai`

## Factories

`AIProviders.xAI`

## Capabilities

- Language
- Image
- Transcription
- Speech
- Video
- Files

## Streaming transcription and current image options

`streamingTranscriptionModel(_:webSocketTransport:)` uses an injectable WebSocket transport. Audio format, sample rate, VAD, partial/final utterances, multi-channel input, finish metadata and producer cancellation follow the published xAI streaming contract. `opus` is also accepted for batch transcription. The requested model ID is retained by transcription factories.

Image capabilities recognize `grok-imagine-image-2.0`; options add 1.5k resolution and auto quality. X Search permits up to 20 allowed/excluded handles. Portable reasoning `max` maps to the provider's highest effort. Existing realtime sessions and Responses calls keep their separate native APIs.

## Rotating credentials

The native `XAIProviderSettings` accepts an optional
`apiKeyProvider` asynchronous throwing closure. It is resolved for each
authenticated request, so short-lived credentials can refresh without recreating
the provider or model. Static `apiKey` settings remain supported. A supplier
failure stops the request before it reaches the transport.

## Current reasoning and stream completion

Shared reasoning `none` maps to `low` with a compatibility warning on current
Grok 4.5, 4.6, 4.7 and 5-family models that cannot disable reasoning. Older
families, `grok-latest` and Grok 4.20 multi-agent retain their existing `none`
behavior. Exact `grok-4.6` maps portable `xhigh` and `max` to `xhigh`; other
models, including `grok-4.7`, currently map them to `high`. Explicit
`xai.reasoningEffort` provider options pass through unchanged.

Responses streams emit citation sources once when incremental annotations are
also repeated in the final output item. Completion-only message items retain
both text and citations, including when an item was announced without deltas.

`XAIProviderSettings.apiKeyProvider` accepts an async throwing key supplier.
It refreshes authentication before native language, files, batch, image, speech,
transcription, video polling and realtime client-secret HTTP requests, and
before each native streaming-transcription WebSocket connection. Static
keys and caller header overrides remain supported; browser-specific transport
and TypeScript catalog mechanics keep their documented native differences.

## Server realtime and caller-storage video

Server realtime connections derive their WebSocket URL from the configured base
path and resolve current credentials before connecting. The client-secret route
retains its canonical `/v1` URL. Conversation intent is supported; transcription
intent fails before I/O. Read normalized usage through `event.usage`, including
cached/modality counts without automatically summing provider snapshots.

Video `output.uploadUrl` selects direct delivery to caller-owned HTTPS storage.
The native unary polling result returns `uploadedVideos` descriptors even when no
download URL exists. Signed upload URLs are removed from returned request/raw
metadata and diagnostics. This does not introduce persisted Async Video operations.
Transcription returns independent word timings and warns when requested timings
are unavailable.


## Notes

xAI mirrors upstream 5.0.40: `XAI_API_KEY`, custom base URL and headers, versioned user-agent suffix, callable/language Responses default, chat/responses/image/video/files aliases, no-argument `speech`/`speechModel` and `transcription`/`transcriptionModel` aliases, Responses provider options and hosted tools with blocked-domain filters and complete unsupported-sampling warnings, Grok 4.6 `xhigh` reasoning and priority service-tier metadata, streamed/generated Responses image-generation calls with prompt and failure results, image generation/editing, Imagine Video 1.5 generation/edit/extend/reference modes with 1080p, reference voices, resilient polling, and terminal moderation/missing-URL errors, `/tts` speech generation with voice/language/output_format, timestamps, pronunciation replacements, trace/usage metadata, and provider options, `/stt` multipart batch transcription with options and word segments, Files API provider references, response metadata, and xAI error schema. Responses Batch uploads requests, forwards callback URLs, paginates durable results, preserves full content/counts, and isolates provider errors or cancellations per item; current parity also preserves complete raw usage, web-search action data, encoded follow-up identifiers, dot-segment-safe IDs, and typed stream failures. The provider-neutral Realtime V4 contract and duplex session are implemented with xAI ephemeral-secret creation, expiry metadata, authenticated WebSocket configuration, session/audio/text/tool/custom event serialization and parsing, pre-open queuing, health replies, cancellation, and close metadata. Browser WebRTC, ProviderV4 type names, ESM-only packaging, Node 22 engines, and workflow serialization helpers remain deferred or JS-only concerns. Native Google and Gateway realtime adapters are available. The 4.0.54 pass adds complete Files V4 metadata/download/delete and cancellable streaming uploads with expiry validation, plus Batch tool content, input-file expiry/metadata, final-assistant finish data, and raw provider finish reasons. The 2026-09-20 pass aligns Responses schema and batch behavior to xAI 5 while retaining chat as a legacy source-compatible Swift shim; new code should use Responses. The 2026-09-27 pass adds current Responses options and Imagine Video 1.5 storage, keyframe, last-frame, and audio controls; image or audio references select reference-to-video even alongside frame images, with a combined three-item voice and audio-reference limit. File/mask image capabilities are now exposed as async Bool? getters; unrecognized models remain unknown. The 2026-10-11 pass: Streaming transcription supports model selection, Opus/VAD controls, interim/final multi-channel reconstruction and producer cleanup over native duplex WebSockets. Imagine Image 2.0 accepts files, 1.5k resolution and auto quality; X search allows 20 handles. The 2026-11-01 reviewed delta adds native per-request async credentials and current portable request/stream fixes where applicable; see WeeklyUpstreamAudit20261101 for exact package dispositions and retained gaps. The 2026-11-08 reviewed delta and retained gaps are documented in WeeklyUpstreamAudit20261108; no full-package or live-service parity is implied.
