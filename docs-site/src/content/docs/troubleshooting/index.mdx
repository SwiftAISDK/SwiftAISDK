---
title: Troubleshooting
description: Diagnose common SwiftAISDK setup and runtime issues.
---

Start with the error type you catch. Most SwiftAISDK failures are an `AIError`
case or a dedicated error struct; [Error handling](../core/error-handling/)
lists them all.

## Platform and toolchain

SwiftAISDK requires Swift 6.3 or later and a deployment target of macOS 12 or
iOS 15 or later. A resolution or build failure that mentions the platform
version usually means your package or app target sets a lower minimum. Raise
`platforms` in your `Package.swift` or the deployment target in Xcode. Some
provider features have their own availability notes on the
[provider pages](../providers/).

## Missing API Key

Provider factories throw `AIError.missingAPIKey(provider:environmentVariables:)`
when no key is passed and none of the provider's environment variables is set.
The `environmentVariables` value lists the names the factory checked.

```swift
do {
    let provider = try AIProviders.openAI()
} catch AIError.missingAPIKey(let provider, let variables) {
    print("Set one of \(variables) for \(provider)")
}
```

Either export the expected variable in the process that runs your code, or pass
the key explicitly:

```sh
export OPENAI_API_KEY="..."
```

```swift
let provider = try AIProviders.openAI(
    settings: ProviderSettings(apiKey: keyFromKeychain)
)
```

Apps launched from Xcode do not inherit your shell environment; set the variable
under **Edit Scheme > Run > Environment Variables**. Do not ship provider keys
inside a distributed app binary. Each provider page under
[Providers](../providers/) lists its variables.

## Unsupported Model

`AIError.unsupportedModel(provider:capability:modelID:)` means the provider
cannot route that model ID to the requested capability. Check the provider page
and make sure you are asking for a language, embedding, image, speech,
transcription, video, or reranking model through the matching factory.

## Streaming fails with a custom transport

Streaming needs a transport that conforms to `AIStreamingTransport`. When a
custom transport only implements `AITransport` (send-only), `generateText`
works but `streamText` throws a non-retryable `AIError.invalidArgument` for the
`transport` argument. SwiftAISDK never falls back to buffering the whole
response. Add `AIStreamingTransport` conformance; see
[Custom Transports](../core/stream-text/#custom-transports).

## Streaming Stops Early

Check the terminal `finishMetadata` reason first. `interrupted` means the
provider stream ended without its completion signal; partial output is kept and
the caller decides whether to retry. A thrown `AIStreamTimeoutError` or
`AIError.timeout` comes from a timeout you configured.

Retries after output has started are opt-in with `streamRetries`; see
[Retry behavior](../core/stream-text/#retry-behavior) and
[Semantic stream timeouts](../core/stream-text/#semantic-stream-timeouts).

## Tool choice violations

A request with `toolChoice` set to `required`, or to a specific tool, throws
`AIToolChoiceViolationError` when the model finishes without making that call.
`toolChoice: none` with a returned tool call throws the same error. The error
keeps `toolChoice`, `finishReason`, `providerID`, `modelID`, and the returned
`content`, so you can log what the model produced. Relax the choice to `auto`,
make the tool description clearer, or retry. See [Tool choice](../core/tools/#tool-choice).

## Downloads or redirects are rejected

Generated files and other provider URLs are downloaded through a protected
path. An `AIDownloadError` usually means one of:

- the host resolved to a private or disallowed address;
- a redirect pointed to a target that failed validation;
- the response exceeded the size limit;
- a custom transport, or a `URLSessionTransport` with an injected session, does
  not implement the validated-download hooks.

These checks protect against server-side request forgery and are not bypassed
by default. [Files](../core/files/#download-transport-security) explains the
contract and the explicit `trustedOrigin` exception.

## Structured Output Fails

Structured output has two failure points:

1. The provider must return JSON text.
2. The JSON must satisfy your schema and decode into the Swift type.

Catch `AIObjectGenerationError` to see the strategy, failure kind and generated
text. Start by logging that text, then simplify the schema until the provider
reliably follows it, or add a `repairText` hook; see
[Structured output](../core/structured-output/#repair-hooks).

## Live smoke tests

The repository's default tests use mock transports and need no credentials.
Optional live smoke tests call real provider APIs, require provider keys, and
may incur charges. They run only when `LIVE_AI_TESTS=1` is set. The command and
the environment variables it reads are listed under "Live Verification" in
[Docs/PortingStatus.md](https://github.com/SwiftAISDK/SwiftAISDK/blob/main/Docs/PortingStatus.md#live-verification).
