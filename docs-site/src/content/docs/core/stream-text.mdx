---
title: Stream text
description: Consume language model output as an async sequence.
---

Use `streamText` when the UI or caller should receive partial output as it is
generated. It returns an `AsyncThrowingStream` of `LanguageStreamPart` values.

```swift
import SwiftAISDK

let provider = try AIProviders.openAI()
let model = try provider.languageModel("gpt-6.1-sol")

for try await part in model.streamText("Write a short haiku about APIs.") {
    switch part {
    case let .textDeltaPart(_, delta, _):
        print(delta, terminator: "")
    case let .finishMetadata(reason, usage, _):
        print("\nFinished: \(reason ?? "unknown")")
        print("Tokens: \(usage?.totalTokens ?? 0)")
    default:
        break
    }
}
```

When you only need text, wrap the stream with `toTextStream(_:)`. It yields
the text deltas, ignores every other part, and still propagates thrown failures:

```swift
for try await text in toTextStream(model.streamText("Summarize Swift actors.")) {
    print(text, terminator: "")
}
```

Streaming emits structured lifecycle parts, not just raw strings. That lets you render text, reasoning, tool input deltas, tool calls, tool approval requests and responses, tool results, source citations, files, raw chunks, response metadata, and finish metadata with one loop.

Breaking out of the loop, cancelling the enclosing task, or aborting the
request's `abortSignal` cancels the remaining provider response.

## Canonical Stream Contract

Built-in language models emit one semantic family for generated content:

- `textStart`, zero or more `textDeltaPart` values, then `textEnd` or `textEndWithCitations`;
- `reasoningStart`, zero or more `reasoningDeltaPart` values, then `reasoningEnd`.

The `textDelta`, `reasoningDelta`, and `finish` enum cases exist for source compatibility with custom models. Built-in providers never pair one of these deltas with a part-aware delta for the same provider token. The high-level facade normalizes these deltas into the canonical lifecycle and `finish` into `finishMetadata`, so match `textDeltaPart` and `finishMetadata` when you consume `streamText`. A custom stream that mixes both delta families in one semantic channel is rejected because equal adjacent strings can be legitimate provider output and cannot be safely deduplicated by value.

Each logical built-in model response emits exactly one terminal `finishMetadata` part after its open content and tool-input blocks have been closed and its final usage and provider metadata are known. A protocol that can carry multiple logical responses on one connection, such as OpenAI Responses, emits one terminal part for each response. A multi-step tool loop likewise has one terminal part per model step. Custom models should emit the same terminal; clean custom EOF without one is preserved rather than assigned a guessed finish reason.

Providers may finish with `interrupted` when the stream ends without its
completion signal. Partial output remains available. The facade skips local
tool execution and automatic continuation for that response; the caller decides
whether to retry. Explicit provider/parse errors retain their error semantics.

The full stream forwards repeatable provider `error` parts as in-band events. Setup, HTTP, framing, and network failures terminate by throwing. If an in-band error closes a provider stream without a terminal event, the facade completes that step with a single `finishMetadata` whose reason is `error`. By default an attempt is not replayed once it has exposed a public part. Callers can opt into the narrower post-start recovery described in [Retry Behavior](#retry-behavior).

Delivered steering messages emit `.steeringMessage(id:message:stepNumber:)`
before that step's provider output. The stream also supports `.requestMetadata`
and `.ping`. Keepalive pings pass through smoothing and retry buffering; they
neither flush pending text nor reset the semantic-output timeout. Add these
cases to exhaustive switches over `LanguageStreamPart`.

## Tool input and approvals

Tool input can arrive before the final tool call. Use `toolInputStart` / `toolInputStartText`, `toolInputDelta`, and `toolInputEnd` parts when you want to show streamed arguments in a UI, and handle `toolApprovalRequest` / `toolApprovalResponse` parts when a tool requires human or policy approval. See [Tools](../tools/) for tool loops and approvals.

Provider-executed tools can emit results with `preliminary == true` for progress displays. Completed step content and tool results include only final outputs. With `toolApprovalSecret` configured, denied tool requests are unsigned and their denial history remains valid for subsequent calls.

## Citations attached to text

`AICitation` identifies the URL or document supporting a text block, with optional
`startIndex`, exclusive `endIndex`, and `citedText`. OpenAI and Anthropic populate
citations independently of the complete retrieved `sources` list. Ranges are
provider offsets into the containing text; preserve their original coordinate
system when applying text transformations.

`TextGenerationResult.citations` flattens the attached citations. Content uses
`.citedText` when citations are present, while uncited output retains `.text`.
Streams close cited blocks with `.textEndWithCitations`; its `citations` property
also exposes the references without matching the case. UI snapshots retain them
in `AIUITextPart.citations`. The `.text` and `.textEnd` constructors remain
available. Exhaustive switches should handle the companion cases as well.

## Retry Behavior

Facade calls retry transient setup failures according to `retryPolicy`. The default
post-start behavior is conservative: after the first public part, a stream
failure ends that attempt.

Set `streamRetries` to a positive count to recover from retryable in-band provider
error events after streaming has started. The failed attempt's tool input, tool
calls/results, finish, usage, and provider metadata do not become step state for
the replacement attempt. When recovery succeeds, the provider error event and
failed terminal state are suppressed. Text and reasoning already delivered to
the caller cannot be retracted, so a replacement attempt can repeat a prefix;
consumers that enable this option should reconcile visible text accordingly.

Thrown transport/framing failures after public output, non-retryable provider
errors, clean empty streams, and output-schema failures do not consume this
post-start retry budget. `retryPolicy` continues to govern setup attempts and
backoff independently.

```swift
for try await part in AI.streamText(
    model: model,
    prompt: "Stream this carefully.",
    retryPolicy: .none,
    streamRetries: 1
) {
    // Render parts.
}
```

Typed `streamText(..., output:)` object and array streams accept the same
`streamRetries` option. A retryable in-band provider error restarts the whole
typed output pipeline with the failed attempt's parsing state discarded. A
JSON, schema, or decoding failure after a complete provider response is not a
provider-stream retry and does not consume this budget.

[Error handling](../error-handling/#retries-and-timeouts) covers `retryPolicy`,
backoff, and aborts for every call type.

## Semantic Stream Timeouts

Use `AIStreamTimeoutConfiguration` when a streaming caller needs to distinguish
the complete-operation deadline, each model-call step, a stalled first output,
or a stall between output parts:

```swift
for try await part in AI.streamText(
    model: model,
    prompt: "Stream this carefully.",
    timeout: AIStreamTimeoutConfiguration(
        totalNanoseconds: 60_000_000_000,
        stepNanoseconds: 30_000_000_000,
        firstChunkNanoseconds: 10_000_000_000,
        chunkNanoseconds: 15_000_000_000
    )
) {
    // Render parts.
}
```

The step/first/inter-chunk timers restart for every model-call step. Only semantic
output disarms or resets them: non-empty text, reasoning, or tool-input deltas,
files, reasoning files, and complete tool calls. Metadata, raw keep-alives,
lifecycle markers, tool results, and empty deltas do not extend the deadline.
A terminal model finish/error disarms first/inter-chunk timers before output
postprocessing or tool work. Every replacement provider attempt starts a fresh
first-output timer. Explicit aborts preserve their caller reason and reason name.
First/inter-chunk failures throw `AIStreamTimeoutError` with `.firstChunk` or
`.chunk`; step and total failures use `AIError.timeout`. The flat
`timeoutNanoseconds` parameter sets only the total deadline.

Total and step budgets include time spent in retry backoff. A step deadline
stays active after the model stream while client-side tools execute; when it
fires, both the provider request and tool context see an aborted signal whose
reason name is `TimeoutError`. Typed `AI.streamText(..., output: Output.*,
timeout: ...)` overloads use the same timeout lifecycle.

## Files and UI snapshots

Streamed file and reasoning-file parts use the same materialization policy as
`generateText`: `data:` and HTTP(S) URLs become inline data before the part is
emitted, while provider references stay opaque. Downloads honor aborts,
redirect validation, private-host rejection, and byte limits; see
[Files](../files/#download-transport-security).

`AIUIMessageStreamReducer.snapshots` can continue an existing
`originalMessage` instead of starting a new assistant message. Its async
`onEnd` callback fires at most once with the final message and an outcome of
`completed`, `aborted`, `failed`, or `unknown`. Consumer cancellation reports
`unknown` with `isCancelled == true`; an `AIAbortError` reports `aborted` with
`isAborted == true`. [Chat](../chat/) shows the session API built on these
snapshots.

## Steering and failed steps

`AI.streamText` accepts `experimentalSteering`, `onStepError`, `onError` and `onAbort`, including the typed `AIOutput` overloads. Pass a fresh object from `AI.experimentalCreateSteering()` and set the desired `maxSteps`. Delivery receipts, `prepareStep.experimentalSteeringMessages` and completed-step steering metadata follow the same rules as [`generateText`](../generate-text/#experimental-steering).

`steering.steer("Use Paris, Texas instead.", interrupt: true)` restarts the active model stream in the same step when it has yet to produce semantic output or start a tool input. The facade closes any already visible empty text and reasoning blocks before emitting the new steering message. The replacement attempt supplies the completed step's request metadata, warnings, usage and terminal part. The step deadline continues across attempts. Once semantic output or tool input has started, an interrupting message waits for the next step boundary.

`onStepError` fires once when a started model step fails before producing a result: a thrown provider/stream error or a stream ending without output or its terminal finish. It reports the actual continuation-step index and completed previous steps. A provider error chunk completes an errored step and invokes `onError`, without a failed-step callback. An abort or timeout invokes `onAbort`, without `onStepError` or `onError`.

`AIStreamTextAbortEvent` contains completed steps and the available abort reason. `AIToolLoopAgent` forwards its constructor callbacks. Ordinary completion preserves the receipt's completion reason; cancelling the consumer settles pending steering as aborted.

## Custom Transports

Provider settings accept `any AITransport`, so unary `generate` calls work with send-only transports. A custom transport used by `stream` must also conform to `AIStreamingTransport` and return response headers plus an incremental `AsyncThrowingStream<Data, Error>` body. SwiftAISDK reports a non-retryable `AIError.invalidArgument` when streaming is requested with a send-only transport; it never falls back to buffering through `send`.

Prodia language generation and the default protocol implementation are simulated streams because their underlying operation is unary. Provider-backed SSE and Amazon EventStream language models use the incremental transport path.

## Advanced

### Incremental HTTP parsing

Built-in HTTP language providers parse the response incrementally, so the first
complete provider event can become a `LanguageStreamPart` while the HTTP
response is still open. A provider end marker such as `[DONE]`, caller abort, or
stopping iteration cancels the remaining response-body read instead of waiting
for EOF.

### URLSession body buffering

`URLSessionTransport` converts response bytes to `Data` only when the body
consumer requests the next element, so an unread or paused body does not build
an unbounded queue. Abort signals, explicit `cancelBody()`, task cancellation
during a read, and dropping the body release the underlying URLSession task.
Response byte limits still apply.

This bounds the SDK's byte-adapter queue only. Foundation can buffer network
data, and higher-level parsers, tool loops, telemetry and application code can
retain content. The SDK does not guarantee constant memory for a whole stream.
